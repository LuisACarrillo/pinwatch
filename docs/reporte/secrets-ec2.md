# Secrets Manager y bastión EC2

## ¿Por qué Secrets Manager y por qué EC2?

Usamos AWS Secrets Manager para guardar fuera del código y del repositorio la llave con la que se firman los JWT y las credenciales de la base de datos. Ahí quedan cifradas con KMS, con acceso controlado por IAM (LabRole) y cada lectura queda auditada. La API lo lee en tiempo de ejecución y lo guarda en memoria 5 minutos, así no agrega latencia ni costo en cada request. Preferimos Secrets Manager sobre las variables de entorno de Lambda, que quedan visibles en la configuración del despliegue, y sobre Parameter Store, porque se integra con RDS y permite que la contraseña de la base se rote automáticamente sin volver a desplegar. La instancia EC2 es un bastión: la base RDS vive en una subred privada sin acceso desde internet, y necesitamos un punto dentro de la VPC para administrarla (migraciones y consultas). Es una `t3.micro` sin ningún puerto abierto y se entra por AWS Systems Manager Session Manager con el rol de la instancia, sin llaves SSH. El acceso se autentica con IAM y las sesiones quedan registradas. Además, un túnel permite correr las migraciones desde la laptop del equipo. El bastión está fuera de la ruta crítica: si el laboratorio lo apaga, la aplicación sigue funcionando y solo se pierde el acceso administrativo, y su costo es mínimo.
